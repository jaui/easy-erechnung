# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Java Swing app (plus CLI Gradle tasks) that creates and validates EN 16931 e-invoices: ZUGFeRD 2 / Factur-X (PDF/A-3 with embedded `factur-x.xml`) and optionally XRechnung (CII). A separate, older OCR flow uses TypeScript run by Bun with local Ollama models. The README (English) is the user documentation. The UI text, Excel sheet/column names, output folder names and Gradle task names are German. Code, comments and commit messages are English, and commits use conventional prefixes (`fix:`, `feat:`, `build:`, `ci:`, `docs:`, `fix(ui):`).

## Commands

```bash
./gradlew test                                   # all JUnit 5 tests (Mustang only, no external validators)
./gradlew test --tests 'de.aronhomberg.PdfMatcherTest'            # one test class
./gradlew test --tests 'de.aronhomberg.PdfMatcherTest.someMethod' # one test method
./gradlew run                                    # GUI (main class ERechnungApp)
./gradlew installDist                            # start scripts under build/install/easy-e-rechnung/bin

# What CI runs end-to-end (on ubuntu/macos/windows, Java 17 and 25):
./gradlew test installDist
./gradlew excelVorlage -PoutFile=build/ci/vorlage.xlsx
./gradlew excelRechnungen -Pexcel=build/ci/vorlage.xlsx -PoutDir=build/ci/out
# second CI job: also downloads the external validators and turns them on
./gradlew pruefprogrammeLaden -Ptools=kosit,verapdf
./gradlew excelRechnungen -Pexcel=build/ci/vorlage.xlsx -PoutDir=build/ci/out -Pxrechnung -Pkosit -Pverapdf

# TypeScript side (Bun)
bun install
bunx vitest run src/bic-check.test.ts
bun run src/ocr.ts --input demo/verify.pdf --output /tmp/result.json --seller-address "…" --seller-tax-no "…"
```

The CLI tasks `excelRechnungen`, `convertRechnungen`, `excelVorlage`, `pruefprogrammeLaden` and `buildERechnung` are defined in `build.gradle.kts`. They take `-P` properties, and the optional switches `-Pkosit -Pverapdf -Pxrechnung -PabweichungErlauben` become `--flags` for the main class. `templates/excel/rechnungen-vorlage.xlsx` is generated by `ExcelTemplateWriter`. If you change the template content, regenerate the file with `./gradlew excelVorlage`.

## Build constraints

- The code must compile with `options.release = 17` even when a newer JDK builds it, so don't use APIs newer than Java 17.
- The JVM defaults in `build.gradle.kts` (`file.encoding`, `stdout.encoding`, `stderr.encoding` = UTF-8) exist because Windows defaults to Cp1252. The code also reads and writes every file and subprocess stream with an explicit UTF-8 charset; keep doing that.
- The `startScripts` task rewrites the Windows classpath to `lib\*` because the full list of jars is longer than cmd.exe allows on one line.
- CI sets `-Djava.awt.headless=true`, so tests must not open windows.

## Architecture (`src/main/java/de/aronhomberg`, one flat package)

**Central data model:** `InvoiceResponse.Invoice` is a JSON-shaped POJO with PascalCase fields. It is the same shape the OCR/LLM pipeline writes, so all three input paths converge on it:
- Excel: `ExcelInvoiceReader` builds it from the `Setup` sheet, the `Kunden` sheet and one sheet per invoice.
- Verified JSON: `ConvertRechnungenToZugferd` reads it from `rechnungen.out/verified/*.json`.
- Classic OCR app: `Main` produces it from the output of `src/ocr.ts`.

`ConvertRechnungenToZugferd.toMustangInvoice` maps it to a Mustang `Invoice`. This class also holds the shared XML generation, PDF embedding and §19/tax helpers (`generateXml`, `embedZugferd`, `allExempt`, `VISIBLE_19_NOTE`, `billingMonth`).

**`ERechnungService`** is the core pipeline that the GUI (`ERechnungApp`) and the CLI mains (`ExcelRechnungenToZugferd`, `ConvertRechnungenToZugferd`) share. It throws exceptions instead of calling `System.exit` and reports progress through a callback.
- `fromData` renders a new visible PDF with `InvoicePdfRenderer`, which uses the bundled Liberation Sans fonts.
- `fromPdf` keeps the user's PDF. It runs `PdfSanitizer` (strips active content), then `PdfToUnicodeFixer` (repairs Word ligature ToUnicode mappings using the installed original font found by `SystemFonts`), then the PDF↔data match check (`plausibility`), then `PdfNoteStamper` (adds the visible §19 UStG note).
- Both then call `finish`: generate the XML, embed it, optionally write XRechnung, then run `Validators`.
- `ERechnungService.validators` is a static, swappable `ValidatorRunner`; tests replace it to simulate a rejected invoice.

**Publish-only-if-valid invariant (`OutputLayout`):** all output is written to a staging folder. `commit` moves it into `<out>/Rechnung_<Nr>/` only when no check has status `FAIL`. Otherwise `keepFailed` puts it in `_letzter-fehlversuch/` and leaves the previous valid invoice untouched. The PDF↔data match check counts as a check too: it is `FAIL` unless `allowMismatch` is set. Data problems (missing required fields, duplicate names, inconsistent VAT) must raise an error that names the sheet and row, never fall back to a guessed value. Keep both rules when changing the pipeline.

**Validators:**
- `Validators` runs Mustang in-process, and KoSIT and veraPDF as subprocesses. Each one can be switched on or off and gets its own traffic light in the GUI.
- External tools are looked up in this order: `$LOCALAPPS`, the user folder (`AppDirs`), `<repo or app>/tools`, then `C:\localapps` / `~/localapps`.
- `ToolDownloader` installs them only when the user asks. Downloads are HTTPS-only to known hosts, SHA-256-checked, zip-slip safe and installed atomically. Its tests use the GitHub release JSON fixtures in `src/test/resources`.

**Classic OCR app (legacy):**
- `Main.java` (~2100 lines) is a separate Swing app, started from `ERechnungApp` via *Extras → Alte OCR-Oberfläche* as a child JVM.
- It shells out to `bun run src/ocr.ts`, resolved relative to the working directory, so it only works when started from the repo. The Bun binary can be set with `EASY_ERECHNUNG_BUN`.
- `ZUGFeRDInvoiceWriter`, `PdfAConverter`, `ERechnungValidator`, `ZugferdEmbeddedReader`, `JsonParser` and `FileUtils` are used only by this path. `Item`/`Product` are shared with `ConvertRechnungenToZugferd`.

**TypeScript (`src/*.ts`, Bun):**
- `ocr.ts` renders the PDF pages, runs OCR with an Ollama vision model and extracts JSON with an LLM.
- `pdf-text-to-json.ts` is the same flow for PDFs that already have a text layer.
- `bic-check.ts` looks up BICs in `data/bundesbank_blz-aktuell-csv-data.csv`.
- LLM output must be reviewed by a human and copied to `rechnungen.out/verified/` before `convertRechnungen` uses it.

## Local data

`rechnungen.in/`, `rechnungen.out/` and `tools/` are git-ignored and contain the user's real invoices and downloaded validators. Don't commit them or modify them as part of a code change. `start.bat` contains machine-specific paths (`C:\localapps\…`).
